# 04. 영상 설계도 형식 v0

> 상태: 확정 v0 (D-26, D-27) · 담당: AI (형식), FE (재생) · 최종 수정: 2026-11-10 · AI/Claude

AI가 영상을 직접 만들지 않는다. AI는 **설계도(장면 목록)**를 쓰고, 브라우저가 그 설계도대로 화면을 그린다(D-05). 이 문서가 AI와 FE 사이의 기준이다. 만들어 보며 고치고, 바꿀 때는 제안서로 한다.
결정 과정과 근거는 [P-AI-02](../coordination/proposals/P-AI-02-blueprint-v0.md), 샘플은 [sandbox/ai/blueprint_v0/](../sandbox/ai/blueprint_v0/)에 있다.

## 설계 원칙

1. **AI는 무엇을 말하고 무엇이 일어나는지만 쓴다.** 위치, 크기, 색, 움직임 속도는 플레이어(FE)가 정한다.
2. **중간 상태는 코드가 계산한다.** AI는 "두 칸 교환" 같은 동작만 쓰고, 바뀐 배열은 플레이어가 계산한다.
3. **평평하고 단순하게.** 부품 안에 부품을 넣지 않는다(구조화된 출력 기능의 제한).
4. **AI가 만든 코드는 실행하지 않는다.** 플레이어는 정해진 부품과 동작 데이터만 해석한다.

## 전체 구조

```text
클립 { version: 0, title, theme: "dark", scenes: [장면] }

장면 {
  id,                    // 클립 안에서 겹치지 않음
  clear,                 // true면 앞 장면의 부품을 모두 지우고 시작. false면 이어서 씀
  lines: [문장],          // 내레이션. 문장마다 음성과 자막이 된다
  texts, slides, diagrams, grids, codes: [부품],   // 없으면 []
  actions: [동작],
  sourcePages: [쪽 번호]   // 옆 패널에 띄울 근거 페이지
}

동작 { line: 문장 번호, do: 동작 이름, target: 대상 id, args: [문자열] }
```

- 모든 id(부품, 노드, 선, 포인터)는 **클립 전체에서** 겹치지 않는다.
- `theme`은 1단계에서 `"dark"`만 쓴다(D-20, D-36). 플레이어 밖의 웹 화면은 화이트다.
- 음성과 문장별 시간(captions)은 설계도에 넣지 않고 클립 결과에 따로 둔다([contracts/data-model.md](../contracts/data-model.md)).

## 번호 기준

| 무엇 | 시작 |
|---|---|
| 페이지 (`sourcePages`, `slides.page`) | 1 |
| 문장 (`line`), 격자 칸, 클립 순서 | 0 |
| 코드 줄 (`markLine`) | 1 |

## 부품 5개

모든 부품에 `id`, `slot`, `hidden`(처음에 숨김 여부)이 있다.

| 부품 | 필드 | 쓰임 |
|---|---|---|
| **texts** | `style`: title / body / keyword / formula, `content` | 제목, 핵심 문장, 키워드, 수식. `$...$` 안은 LaTeX이고 KaTeX로 그린다 |
| **slides** (원본 조각) | `page`, `box`: [x, y, w, h] | 차트, 사진처럼 다시 그릴 수 없는 것. `page`는 그 장면의 `sourcePages`에 있어야 한다 |
| **diagrams** | `layout`: row / column / tree / layers / cycle, `nodes`: [{id, label, shape: box / circle, hidden?}], `edges`: [{id, from, to, label?, hidden?}] | 흐름도, 계층, 구조도, 신경망, 상태 그래프 |
| **grids** | `cells`: [[문자열]], `indexLabels`: true / false, `pointers`: [{id, label, row, col, hidden}] | 배열(한 줄), 행렬, 표. 줄마다 칸 수가 달라도 된다 |
| **codes** | `language`, `lines`: [문자열] | 코드, 의사코드 |

- 다이어그램 배치: row, column은 `nodes` 순서대로 놓는다. cycle은 `nodes` 순서대로 원을 따라 놓는다. tree와 layers는 `edges`(from = 부모 또는 앞 층)로 위치를 계산한다.
- 노드와 선의 `hidden`은 생략할 수 있고, 생략하면 false다.

## 자리 (slot)

- 자리는 `top`, `middle`, `bottom`, `full` 4개다. 세로 화면을 위, 가운데, 아래로 나누고, `full`은 화면 전체다.
- **한 자리에 동시에 보이는 부품은 1개다.** 숨긴 부품은 같은 자리에 여러 개 두고 show/hide로 바꿔 끼운다.
- **`full` 부품이 보이는 동안 다른 부품은 보일 수 없다.** 세로로 긴 그림이나 페이지 전체를 크게 보여 줄 때 쓴다. 가로 슬라이드는 세로 화면에서 폭을 꽉 채워도 높이의 약 1/3이라, 보통은 3칸 자리 하나와 `focus`로 충분하다.
- 자막은 자리와 상관없이 FE가 항상 보여 준다.

## 동작 12개

| 동작 | 대상 | args | 뜻 |
|---|---|---|---|
| show / hide | 모든 부품, 노드, 선, 포인터 | 없음 | 나타나기, 사라지기 |
| highlight / unhighlight | 텍스트, 노드, 선, 포인터, 격자, 코드 | 격자면 칸 위치 | 강조 켜기, 끄기 |
| move | 포인터 | 칸 위치 | 포인터 이동 |
| swap | 격자 | 칸 위치 2개 | 두 칸 값 교환 |
| setValue | 격자 | 칸 위치, 새 값 | 칸 값 바꾸기 |
| setText | 텍스트 | 새 내용 | 글이나 수식 바꾸기 |
| focus | 원본 조각 | `"x,y,w,h"` | 그림의 한 부분 확대 |
| mark / unmark | 원본 조각 | `"x,y,w,h"`, 라벨(생략 가능) | 강조 상자와 짧은 라벨 표시, 지우기 |
| markLine | 코드 | 줄 번호 | 지금 설명하는 줄 표시 |

- 칸 위치: 한 줄 배열은 `"4"`, 2차원은 `"1,3"`, 범위는 `"0-3"`.
- 강조는 **자리(칸)**에 붙는다. 두 칸을 교환해도 강조는 그 칸에 남는다.
- **좌표:** `box`, `focus`, `mark`는 모두 **원본 페이지 기준 0~1 비율**이다. `focus`와 `mark` 영역은 그 부품의 `box` 안에 있어야 한다.

## 시간 규칙

- 기준은 **음성의 현재 재생 시간**이다. 문장별 시작, 끝 시간은 captions에 있다.
- 동작은 그 문장이 **시작될 때** 적힌 순서대로 실행한다. 간격과 속도는 FE가 정한다.
- 다음 문장이 시작되면 이전 문장의 동작은 모두 **최종 상태로 바로 맞춘다.**
- 쉼: 문장 사이 0.3초, 장면 사이 0.6초. 새 장면은 앞 장면 마지막 문장의 끝 시간(endSec)에 바뀐다.
- **상태 복원:** 원본 설계도는 바꾸지 않는다. 화면 상태는 클립 시작부터 그 시점까지의 동작을 다시 계산해서 만든다. 그래서 뒤로 탐색, 반복, `clear: false` 장면에서도 같은 화면이 나오고 같은 동작이 두 번 적용되지 않는다. 일시정지하면 음성과 동작이 모두 멈춘다.

## 크기 상한

넘치면 글자를 줄이지 않고 장면을 나눈다. AI 프롬프트에 넣고 검사기가 확인한다. FE가 그려 보고 조정한다.

| 대상 | 상한 |
|---|---|
| texts | title 20자, body 60자, keyword 15자, formula 한 줄 |
| diagrams | 노드 6개, 선 8개, 노드 라벨 12자. tree는 깊이 3 이하·노드 7개, layers는 3층 × 층당 4개 |
| grids | 한 줄 배열 12칸, 2차원 6×6, 표 5행 × 4열, 칸 내용 10자. 3자를 넘는 칸이 하나라도 있으면 표로 본다 |
| codes | 12줄, 한 줄 40자 |
| slides | mark 라벨 10자, 동시에 보이는 mark 3개 |
| 장면 | 문장 5개, 문장 하나에 동작 5개 |

## 검사기

- Python 검사기 하나를 AI가 관리하고 BE가 가져다 쓴다(D-27). 위치와 사용법은 [contracts/pipeline.md](../contracts/pipeline.md).
- 검사하는 것: 필드와 값 종류, id 중복과 참조, 번호 범위, 실제 PDF 페이지 수 안의 페이지, 좌표 범위, 자리 규칙(동작을 따라가며), 크기 상한, 동작 순서, FE가 지원하는 배치 목록.
- **지원 배치 목록:** 검사기 설정에 FE가 구현한 다이어그램 배치만 넣는다. AI는 목록 안의 배치만 쓴다.
- 형식 검사는 내용이 맞는지까지 보장하지 않는다. 내용 품질은 AI가 평가 체크리스트로 따로 본다.
- `sandbox/ai/blueprint_v0/validate.js`는 이전 초안이며 기준이 아니다.

## 표현이 어려울 때

어떤 부품으로도 표현하기 어려우면 원본 조각을 띄우고 `focus`와 `mark`로 설명한다. 그래서 표현 때문에 클립이 실패하지는 않는다.

## 알려진 한계와 2단계 후보

- 합병 정렬: 격자 하나를 여러 줄(왼쪽 절반, 오른쪽 절반, 결과)로 쓴다. 값이 다른 줄로 옮겨 가는 움직임 없이 칸 값이 새로 생긴다.
- 삽입 정렬: 값이 밀리는 움직임 없이 `setValue`로 칸 값이 차례로 바뀐다.
- 2단계 후보: `shift`(한 칸씩 밀기), 줄 사이 값 옮기기, 슬라이드 위 화살표, 한 자리에 배열 여러 개, 함수 그래프 부품, 아이콘(라우터, 서버 등), 밝은 테마.
- AI가 알고리즘 과정을 틀리게 설명할 위험은 남는다. 중간 상태는 코드가 계산하지만 동작 순서 자체가 틀릴 수 있다.
