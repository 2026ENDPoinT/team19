팀 공유 현황과 요청은 [FE 역할 문서](../../coordination/roles/fe.md), 공용 결정은 [결정 기록](../../coordination/decisions.md)에 둔다. 이 폴더에는 FE 코드 설명과 학습 기록만 둔다.

## 작업 방식

이 방식을 선택한 이유는 AI가 코드를 전부 작성하고 사용자가 충분히 이해하지 못한 채 진행하면, 나중에 수정하거나 리팩토링할 때 코드 구조와 동작을 다시 파악하는 시간이 필요하고 작업이 더 오래 걸릴 수 있기 때문이다. 처음부터 함수·컴포넌트를 한 블록씩 직접 붙여 넣고 역할과 동작을 확인하며 이해를 쌓는다. 코드 작성 속도뿐 아니라 이후 스스로 수정할 수 있는 이해도를 목표로 한다.

- 기본은 사용자가 코드를 직접 붙여 넣는다. 휴대폰 작업 중에는 요청에 따라 Codex가 적용하며, 적용한 코드 전체 블록과 설명을 함께 제공한다.
- Codex는 함수 또는 컴포넌트 하나씩 코드, 정확한 교체 위치, 역할, 확인 방법을 설명한다.
- 한 줄씩 지나치게 나누거나 전체 앱 코드를 한 번에 제공하지 않는다.
- 화면 이름은 사용자 요청에 따라 ‘강의 숏폼’을 사용한다. 팀 전체 이름 확정 기록과는 구분한다.

## 2026-11-06

### 구현한 것

- React + TypeScript + Vite 초기 설정. 초기 커밋: `9bf904e`.
- `Header`: 서비스 이름과 아이콘.
- `UploadIntro`: 업로드 화면의 소개 문구.
- `PdfUpload`: 파일 선택, 파일 이름·크기 표시, PDF 확장자 검사, 선택 교체.
- 업로드 카드 안 드래그 앤 드롭, 여러 파일 드롭 오류 안내.
- 기본 CSS로 흰 배경·파란 강조색의 카드 스타일 구현. Tailwind는 설치하지 않았다.

### 함수별 역할

| 함수 | 역할 |
|---|---|
| `selectFile` | 버튼 선택·드롭에서 공통으로 쓰는 파일 검사와 상태 저장 |
| `handleFileChange` | 파일 선택 창의 첫 파일을 전달하고 입력 값을 초기화 |
| `handleDrop` | 브라우저 기본 열기 동작을 막고 단일 파일을 전달 |

### 확인한 것과 한계

- 사용자: 앞 단계 파일 선택과 카드 표시 동작 확인.
- Codex: 현재 코드의 `npm run build` 통과, `git diff --check` 통과.
- 최신 드래그 앤 드롭 동작은 브라우저에서 추가 확인 필요.
- 파일은 브라우저 상태에만 있으며 서버 업로드·PDF 분석은 아직 없다.
- PDF 검사는 확장자 기반의 화면 안내다. 서버 검증을 대체하지 않는다.
- 모드 선택, 분석 상태, 클립 목록, 세로 피드는 미구현.
- Figma는 모드 선택·클립 목록까지 만든 시제품을 참고한다. 생성 순서와 모드 세부는 임시안이다.


## 2026-11-09 추가 기록

- 이전 날짜의 구현/미구현 목록은 당시 상태다. 최신 현황은 FE 역할 문서를 따른다.
- 추가 구현: 다크 테마, 학습 모드 선택, 샘플 분석 상태·클립 목록, PDF 제거/빈 파일 검사/드래그 강조, 홈·초기화, 모바일 스타일, 중복 CSS 정리.
- `sampleApi.readSample`: BE cases.json에서 응답 본문을 복사해 반환. 타입 단언은 런타임 검증을 대체하지 않는다.
- `SampleClipFlow`: 임시 타이머로 대기/진행/완료 상태를 보여주며 화면 이탈 시 해제한다. 실제 서버나 폴링은 아니다.
- `App`: 파일·모드·화면 상태 공유. `goHome`은 선택 유지, `startNewPdf`는 상태 초기화와 key 변경으로 자식 화면도 초기화한다.
- `PdfUpload`: 파일 선택/드롭을 공통 검사로 연결하고 제거·빈 파일 오류·드래그 진입/이탈 강조를 처리한다.
- `UploadIntro`: 위치에 의존하던 first-child 선택자 대신 전용 className을 사용한다.
- 검증: 각 단계 npm run build와 git diff --check 통과. 최근 화면은 브라우저 검증 전이다.
