# 01. 제품 정의

> 상태: 논의중 · 담당: 전원 (정리: AI) · 최종 수정: 2026-11-06 · AI/Claude

## 한 줄 정의

강의 PDF를 올리면 학습 단계에 맞춰 개념과 예시 단위로 나눈 세로 숏폼 영상 시리즈를 만들어 주고, 쇼츠처럼 넘겨 볼 수 있는 웹 서비스.

## 왜 만드나 (강현 노트)

- 우리는 개념과 예시 단위로 이해한다. 그런데 강의 내용은 연속적이고 양이 많아서 버겁고 막막하다. 롱폼을 피하는 현상은 공부에서도 똑같다.
- 그래서 가볍게 볼 수 있는 개념 숏폼이 필요하다.
- 기준은 유튜브의 일반 영상이 아니라 **내 수업의 강의자료**여야 한다. 시험은 결국 강의자료, 수업 필기, 기출에서 나오기 때문이다.
- 기존 요약형 AI(UnivAI, Gpai 등)는 글 요약이다. 강의자료의 개념을 영상으로 하나씩 설명해 주는 서비스는 드물다. 비교는 [02-competition.md](02-competition.md)에 있다.

## 사용 흐름 (초안)

1. 강의 PDF를 올린다.
2. 지금 학습 단계에 맞는 모드를 고른다. 예: 처음 보기, 복습, 시험 대비. 이름과 기준은 미정이다([05](05-segmentation-and-modes.md) 참고).
3. AI가 자료를 분석해서 클립 목록을 보여준다. 무엇을 몇 개로 나눌지가 여기서 정해진다.
4. 클립이 만들어지는 대로 세로 피드에 나타난다. 생성 흐름은 미정이다(Q-AI-05).
5. 쇼츠처럼 위아래로 넘겨 보고 반복 재생한다. 화면 옆에는 그 클립이 참고한 원본 페이지가 보인다.
6. (2단계) 마음에 드는 클립을 저장하고, 아쉬운 클립은 요청을 적어서 다시 만든다.

## 영상이 갖춰야 할 것 (강현 노트)

- 세로 비율이다. 길이는 내용에 따라 달라진다(D-02).
- 예시는 시각화로 설명한다. 간단한 도형이나 강의자료의 그림을 쓰고, 화살표를 움직이거나 강조 표시를 한다.
- 알고리즘처럼 과정이 있는 내용은 정지 그림보다 움직임으로 보여준다. 배열이 어떻게 바뀌는지, 숫자가 어떻게 이동하는지, 피벗이 어떻게 움직이는지를 보여주고, **헷갈리는 종료 조건을 언제 만족하는지까지** 포함한다.
- 강의자료를 그대로 옮기지 않는다. AI의 사전 지식으로 보충 설명을 한다.
- 너무 압축하지 않는다. "당연히 이해했겠지" 하고 건너뛰는 것이 가장 나쁜 실패다.
- 별로 중요하지 않은 것은 굳이 넣지 않는다. 다만 무엇이 중요한지는 모드에 따라 다르다.
- 분량이 많으면 개념 영상과 예시 영상을 나눈다.
- 화면 스타일 예: 검정 배경에 수식과 숫자가 움직이는 형태, 흰 배경에서 그래프 노드가 연결되는 형태. 특정 유튜버의 영상을 그대로 따라 하지는 않는다.

## 대상 자료

- 목표(팀장 의견): PDF 강의자료라면 과목과 관계없이 대부분 동작한다. 코드 비중이 적은 과목(네트워크, 소프트웨어공학 등)도 포함한다.
- 팀원 의견: CS 안에서도 특정 과목 하나를 먼저 성공시키고 넓히자.
- 첫 목표 범위는 논의중이다(Q-AI-02).
- 테스트용 예시 자료는 알고리즘 3강 분할정복이다. 이 자료에 맞춰서 만들지는 않는다.

## 구현 범위 (D-04, 목표는 2단계까지)

| 단계 | 내용 |
|---|---|
| 1단계 (필수) | PDF 업로드 → 모드 선택 → 클립 여러 개 생성 → 세로 피드 재생과 원본 페이지 표시. 결과는 서버에 저장해서 새로고침해도 남는다. 로그인은 없다. |
| 2단계 (목표) | 내 강의함(지난 업로드 다시 보기), 클립 저장, 요청을 적어서 클립 하나 다시 만들기 |
| 3단계 (여유) | 로그인, 앱 |

## 이번 범위에서 하지 않는 것

- 수업 필기와 기출 문제를 추가로 입력받는 기능(D-03)
- 자체 AI 모델 학습(파인튜닝)
- 영상 파일(MP4) 내보내기. 일단 웹 재생만 한다.
- 앱(3단계 여유분)
