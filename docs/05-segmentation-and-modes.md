# 05. 자료 나누기와 학습 단계 모드

> 상태: 확정 (D-11, D-12, D-29, D-57) · 담당: AI (강현) · 최종 수정: 2026-11-14 · AI/Claude

"PDF 하나를 어떤 클립 몇 개로 나눌 것인가." 강현 노트의 표현으로는 **이 프로젝트의 핵심 품질**이다. AI 담당 영역이다. 프롬프트는 [pipeline/prompts/outline_system.md](../pipeline/prompts/outline_system.md), 검사는 [pipeline/outline.py](../pipeline/outline.py)에 있다.

## 강현의 관점: 학습 단계가 다르다

시험 준비는 단계별로 필요한 것이 다르다.

1. 강의자료를 처음 접할 때
2. 복습하면서 내용을 외워 나갈 때
3. 시험 대비로 지엽까지 꼼꼼히 볼 때

그래서 **클립마다 중요도를 붙이는 방식이 아니라**, 모드에 따라 나누는 방식과 **클립 수 자체**가 달라지는 구조로 간다(D-11).

## 모드: 입문 · 기본 · 심화 (D-57)

API 값은 그대로 `intro` / `review` / `exam`이다(D-29). 정의 과정은 [P-AI-10](../coordination/proposals/P-AI-10-modes.md).

| | 입문 (`intro`) | 기본 (`review`) | 심화 (`exam`) |
|---|---|---|---|
| 강의 반영 | 목차 수준. 큰 주제의 이름과 흐름만 가져온다 | 강의 전체. 설명은 강의 내용 절반, AI의 쉬운 풀이·직관 절반쯤 | 90~100%. 내용 페이지를 거의 다 다룬다 |
| 설명의 재료 | 대부분 AI 일반 지식: 무엇인지, 왜 필요한지, 비유 | 강의 + AI 보충 반반 | 강의에 충실. 조건·예외·표기·증명·예시까지 |
| 말투 | 아주 쉽게, 짧은 문장 | 쉽지만 전문성을 잃지 않게 | 정확한 용어와 표기 |
| 클립 길이 | 40~70초 | 1~1.5분 | 1~2분(상한 120초, D-41) |
| 클립 수 | 내용 10쪽당 1개, 2~5개 | 내용 5쪽당 1개, 3~12개 | 내용 3쪽당 1개, 4~20개 |
| 검사 | | | 내용 페이지의 90% 이상이 어느 클립의 근거 페이지에 들어가야 한다 |

- 클립 계획에 `mode`가 들어가고, 설계도 단계가 모드별 말투와 길이를 따른다.
- 분할정복 57쪽 실측(11/14): 입문 4개(38~43초), 기본 10개(57~80초).

## 나누기 원칙 (강현 노트에서)

- 진짜 핵심 위주로 나눈다.
- PPT 한 장이 여러 개념으로 나뉠 수 있고, 여러 장이 하나의 개념을 위해 필요할 수도 있다. 예: 의사코드를 줄별로 따라가기.
- 양이 많으면 개념 클립과 예시 클립을 나눈다. 예시 클립 제목은 "예시: "로 시작한다.
- 제목은 설명형으로 쓴다(무엇을 배우는지 보이게).
- 너무 압축하지 않는다. "당연히 이해했겠지" 하고 건너뛰지 않는다.
- 별로 중요하지 않은 것을 굳이 넣지 않는다.
- 헷갈리는 지점(종료 조건 등)은 빠뜨리지 않는다.
- 강의자료를 그대로 옮기지 않고, AI 사전 지식으로 보충한다.
- 무엇이 중요한지는 자료 속 표시("자주 하는 실수" 같은 박스)에 기대지 않는다. 그런 표시는 AI 생성 자료에만 흔하다. 정의, 조건, 예외, 강조된 공식, 반복되는 내용 같은 단서로 AI가 판단한다.

## 처리 단계

1. **추출**: 쪽마다 글자와 페이지 그림(로컬, 무료). 강의마다 한 번(D-12).
2. **페이지 해설**: 페이지 그림까지 AI에 보내 도식·그래프를 글로 설명한다. 표지·목차·행정 안내는 표시를 붙여 분할에서 거른다. 강의마다 한 번.
3. **분할 계획**: 고른 모드마다 따로 만든다. 제목, 종류(`concept`/`process`/`example`/`compare`), 근거 페이지, 선수 클립, 핵심 메모. 검사에 실패하면 한 번 다시 만든다.
4. **클립 설계도**: 클립마다 [04](04-video-blueprint.md)의 설계도를 만든다.

## 좋은 분할 체크리스트 (평가용)

- [ ] 클립 하나가 하나의 질문에 답한다. 예: "피벗은 어떻게 고르나?"
- [ ] 제목만 봐도 무엇을 배우는지 알 수 있다.
- [ ] 근거 페이지가 적혀 있다.
- [ ] 앞 클립을 봐야 이해되면 그 선수 클립이 표시되어 있다.
- [ ] 한 클립에 너무 많은 단계를 압축하지 않았다.
- [ ] 모드의 의도에 맞는 깊이다.
- [ ] 개념 클립과 짝이 되는 예시 클립이 있다(필요한 경우).

## 품질 확인 방법

- 프롬프트와 설계도 형식에 특정 자료의 내용이나 구성(예: 특정 박스 이름)을 넣지 않는다.
- 여러 과목으로 확인했다: 알고리즘(분할정복, 그리디), 소프트웨어공학, 트랜스포머, 강화학습, 파이썬, 경제의 이해. 평가 결과는 [samples/eval/](../samples/eval/README.md)과 [sandbox/ai/](../sandbox/ai/)의 실험 기록에 있다.
- 남은 과제: 사람이 만든 "이상적인 분할" 정답지와의 비교, 확인용 자료를 따로 떼어 둔 평가는 하지 못했다.
