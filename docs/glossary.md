# 용어집

> 상태: 계속 추가 · 담당: 전원 · 최종 수정: 2026-11-14 · AI/Claude

모르는 단어가 나오면 여기서 찾는다. 없으면 에이전트에게 설명을 부탁하고, 여기에 한 줄 추가한다.

## 서비스 구조

| 용어 | 뜻 |
|---|---|
| 프론트엔드 (FE) | 사용자가 보는 화면. 브라우저에서 돈다. |
| 백엔드 (BE) | 화면 뒤에서 일하는 서버. 파일 저장, 데이터 관리, AI 호출을 맡는다. |
| API | 프론트엔드와 백엔드가 주고받는 약속된 요청 창구. "이 주소로 이렇게 요청하면 이렇게 답한다." |
| 엔드포인트 | API의 개별 창구 하나. 예: "PDF 올리기" 창구 |
| 계약 (contract) | 파트끼리 주고받는 데이터의 모양과 API를 미리 정해둔 약속. `contracts/` 폴더에 있다. |
| 목업, 샘플 데이터 | 진짜 AI를 부르지 않고 미리 만들어둔 가짜(또는 저장된) 결과. 이걸로 각자 동시에 개발한다. |
| 작업 (job) | 오래 걸리는 일(영상 생성 등)을 접수해 두고 번호로 진행 상태를 확인하는 방식 |
| 폴링 | 화면이 몇 초마다 "다 됐어?" 하고 서버에 물어보는 방식 |
| 배포 | 내 컴퓨터가 아닌 인터넷 서버에 올려서 다른 사람도 접속하게 하는 것 |
| GitHub Pages | GitHub가 저장소의 화면 파일을 `github.io` 주소로 무료로 올려 주는 기능. 화면만 올릴 수 있고 서버는 못 돌린다 |
| 터널 | 내 컴퓨터에서 켠 서버를 인터넷 주소로 열어 주는 연결. 우리는 Cloudflare 임시 터널(`trycloudflare.com`)을 썼다 |
| CORS | 브라우저가 다른 주소의 서버에 요청해도 되는지 서버가 허락하는 규칙. 허락 목록에 화면 주소가 있어야 한다 |
| 데이터베이스 (DB) | 데이터를 표처럼 저장하고 찾아 쓰는 프로그램 |
| 렌더링 | 데이터를 화면에 실제로 그리는 것 |

## AI 관련

| 용어 | 뜻 |
|---|---|
| LLM | Claude, GPT 같은 대형 언어 모델 |
| 프롬프트 | AI에게 주는 지시문 |
| 토큰 | AI가 글을 세는 단위. 비용이 토큰 수로 계산된다. 한글 한 글자가 대략 토큰 1개 안팎이다. |
| 입력 토큰, 출력 토큰 | AI에게 보낸 양과 AI가 쓴 양. 보통 출력이 더 비싸다. |
| 구조화된 출력 | AI가 정해진 형식(JSON)으로만 답하도록 강제하는 기능 |
| TTS | 글을 음성으로 읽어주는 기술 (Text To Speech) |
| 파인튜닝 | AI 모델을 우리 데이터로 추가 학습시키는 것. 이번에는 하지 않는다. |

## 이 프로젝트에서 쓰는 말

| 용어 | 뜻 |
|---|---|
| 클립 | 숏폼 영상 한 개 |
| 모드 | 학습 단계에 따라 자료를 나누는 방식. 입문(`intro`) / 기본(`review`) / 심화(`exam`) (D-57) |
| 검사기 | AI가 쓴 설계도가 형식과 규칙을 지켰는지 확인하는 Python 코드. 떨어지면 AI가 한 번 다시 쓴다 |
| 자리 (slot) | 세로 화면의 위(top), 가운데(middle), 아래(bottom). 부품이 놓이는 곳 |
| near | 글을 자리 대신 다른 부품·노드·칸 옆에 붙이는 방식(이름표, 값 표시) |
| 도장 (stamp) | 화살표·노드·글 위에 찍는 X 또는 O 표시. 핵심 부정·대비에만 쓴다 |
| 구분선 (divide) | 격자 칸 사이에 긋는 점선. 두 배열을 나누거나 반으로 나눌 때 |
| 장면 단위 음성 | 장면 하나를 한 번에 읽혀 톤을 맞춘 뒤 문장별로 자르는 방식(D-62) |
| 학습 예시 | 미리 생성해 화면에 함께 묶어 둔 클립. 서버 없이 재생된다 |
| 내 강의함 | 로그인 없이 브라우저마다 만든 기기 ID로 내가 올린 강의만 보여 주는 목록 |
| 기능 동결 | 이 시각 이후로 새 기능을 넣지 않고 버그만 고치는 것 |
| 분할 계획 (outline) | PDF를 어떤 클립 몇 개로 나눌지 정한 목록 |
| 영상 설계도 (blueprint) | AI가 쓰는 "장면 목록". 화면에 무엇을 놓고 어떻게 움직일지 적혀 있고, 브라우저가 이걸 보고 영상을 그린다. |
| 부품 | 설계도에 쓰는 화면 요소. 예: 숫자 배열, 화살표, 그래프, 수식 |
| 근거 페이지 | 클립이 참고한 원본 PDF 페이지 |

## git, GitHub

| 용어 | 뜻 |
|---|---|
| 저장소 (repository) | 프로젝트 폴더와 그 변경 기록 전체 |
| 커밋 (commit) | 변경 내용을 기록 하나로 저장하는 것 |
| 푸시 (push) | 내 기록을 GitHub에 올리는 것 |
| 풀 (pull) | GitHub의 최신 기록을 내 컴퓨터로 받는 것 |
| 충돌 (conflict) | 두 사람이 같은 곳을 동시에 고쳐서 git이 어느 쪽을 쓸지 모르는 상태. 사람이(또는 에이전트가) 골라줘야 한다. |
| 브랜치 (branch) | 기록을 갈래로 나눠서 따로 작업하는 공간 |
| PR (Pull Request) | 내 브랜치의 변경을 본 갈래(main)에 합쳐 달라는 요청 |
| `.env` | API 키 같은 비밀 값을 넣는 파일. 절대 GitHub에 올리지 않는다. |
