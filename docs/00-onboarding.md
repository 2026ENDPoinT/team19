# 00. 처음 시작하기

> 상태: 초안 · 담당: AI(팀장) · 최종 수정: 2026-11-06 · AI/Claude

이 문서는 개발 경험이 많지 않아도 따라 할 수 있도록 썼다. 막히면 쓰는 에이전트에게 "이 문서 단계 N에서 막혔어"라고 말하면 된다.

## 1. 준비물

- GitHub 계정
- git (코드 변경 기록 도구)
- AI 에이전트 하나: Claude Code 또는 Codex
  - Claude Code 설치: <https://code.claude.com/docs/en/quickstart>
  - Codex CLI 설치: OpenAI 공식 안내를 따른다 (예: `npm i -g @openai/codex`)

## 2. 저장소

팀 저장소는 해커톤 운영 측이 할당한 `2026ENDPoinT/team19`다.
주소: <https://github.com/2026ENDPoinT/team19>

**팀장이 처음 한 번 할 일: 설계 초안 올리기**

1. 저장소를 받는다: `git clone https://github.com/2026ENDPoinT/team19.git`
2. 운영 측이 미리 넣어둔 파일(README 등)이 있는지 확인한다.
3. 설계 초안 zip 안의 `lecture-shorts` 폴더 **안에 있는 내용물**을 `team19` 폴더 맨 위에 넣는다. `AGENTS.md`와 `CLAUDE.md`가 저장소 맨 위에 있어야 에이전트가 읽는다. `.gitignore`도 같이 옮겨졌는지 확인한다.
4. 커밋하고 올린다.

   ```bash
   git add .
   git commit -m "[AI] 설계 초안"
   git push
   ```

에이전트에게 맡겨도 된다. 빈 폴더에서 Claude Code를 열고 이렇게 말한다.
> https://github.com/2026ENDPoinT/team19 저장소를 받아서, lecture-shorts.zip 안 lecture-shorts 폴더의 내용물을 저장소 맨 위에 넣어줘. 기존 파일과 겹치는 게 있으면 덮어쓰기 전에 알려주고, 커밋해서 올려줘.

**팀원 권한:** 운영 측이 팀원을 이미 넣어뒀는지 확인한다. 안 되어 있으면 운영 측에 요청한다.

## 3. 팀원이 할 일: 저장소 받기

1. 저장소 접근 권한이 있는지 확인한다(초대 메일이 왔으면 수락).
2. 터미널에서 `git clone https://github.com/2026ENDPoinT/team19.git`을 실행한다. 또는 에이전트에게 "이 주소의 저장소 받아줘"라고 말한다.
3. 받은 `team19` 폴더에서 에이전트(Claude Code 또는 Codex)를 연다.

## 4. 처음 한 번만: 나를 소개하기

에이전트에게 `시작 루틴 해줘`라고 말한다. 처음이면 에이전트가 이름, 역할, 쓰는 도구를 물어보고 `me.local.md` 파일을 만든다.
이 파일은 내 컴퓨터에만 있고 GitHub에는 올라가지 않는다. 에이전트는 이 파일을 보고 내가 어떤 역할인지 안다.

## 5. 매일 쓰는 요청 문장

| 언제 | 에이전트에게 할 말 |
|---|---|
| 작업 시작할 때 | `시작 루틴 해줘` |
| 제안서에 의견 달 때 | `P-AI-01 제안서 읽고 내 역할 입장에서 의견 써줘` |
| 다른 역할에게 물어볼 때 | `BE한테 이거 질문으로 남겨줘: (질문 내용)` |
| 문서를 바꾸고 싶을 때 | `이 부분 바꾸자는 제안서 만들어줘: (바꾸고 싶은 내용)` |
| 모르는 게 있을 때 | `03 문서에서 이 부분 쉽게 설명해줘` |
| 작업 끝날 때 | `종료 루틴 해줘` |

에이전트는 [AGENTS.md](../AGENTS.md)에 적힌 규칙대로 움직인다. 위 문장들은 그 규칙을 부르는 신호다.

## 6. 꼭 지킬 것

- API 키(유료 AI를 쓰기 위한 비밀번호)는 절대 GitHub에 올리지 않는다. 메신저로 따로 주고받는다.
- 다른 역할의 파일은 고치지 않는다. 바꾸고 싶으면 질문이나 제안서로 남긴다.
- 작업 시작 전에는 받고(pull), 끝나면 올린다(push). 에이전트의 시작 루틴과 종료 루틴이 대신 해준다.
- 급한 일은 팀 메신저로 이야기하되, 정해진 내용은 꼭 파일에 남긴다. 파일에 없는 결정은 없는 결정이다.
