# 설계도 생성 첫 비교: Sonnet 5.5 vs GPT-6.1 Terra

> 상태: 실험 기록 (Q-AI-07 첫 데이터) · 담당: AI · 최종 수정: 2026-11-09 · AI/Claude

## 조건

- 클립 계획: [samples/clip-01/plan.json](../../samples/clip-01/plan.json) (분할정복 18~20쪽, 합병 과정)
- 같은 프롬프트([pipeline/prompts/blueprint_system.md](../../pipeline/prompts/blueprint_system.md)), 글자만(페이지 해설 없음), 한 번씩

## 결과

| | Sonnet 5.5 (effort high) | GPT-6.1 Terra |
|---|---|---|
| 형식 검사 | 첫 시도 통과 | 첫 시도 통과 |
| 비용 | $0.115 (입력 8.2천, 출력 9.5천 토큰) | $0.020 (입력 5.3천, 출력 3.0천 토큰) |
| 시간 | 69초 | 39초 |
| 길이 | 장면 7, 문장 28, 약 117초 | 장면 5, 문장 23, 약 93초 |
| 화면 변화 | 강조 16번. 비교하는 두 칸을 매번 강조 | 강조 9번. 포인터 이동 위주 |
| 내레이션 | 자연스럽다. 숫자는 숫자로 읽음 | 숫자를 "육, 십오"처럼 한글로 써서 어색하다("육과 이를 겨뤄 이를 저장") |
| 사실 | **틀림**: 슬라이드 표를 따라 "열 번째 대결", "비교는 열 번" | **맞음**: "이 예에서는 아홉 번, 최대는 열 번" |

## 발견

- **19쪽 슬라이드 표가 틀렸다.** "29 vs 30"은 10번째가 아니라 9번째 비교다. 10은 최대 비교 횟수(a+b−1)다. 강의자료도 틀릴 수 있으므로 "페이지에 근거"만으로는 부족하다. 계산이 있는 예시는 모델이 직접 다시 세게 해야 한다.
- 프롬프트의 "기호를 읽을 수 있게 쓰라"는 규칙을 Terra는 숫자에까지 적용했다. 숫자는 그대로 두라고 명시해야 한다.
- 두 모델 모두 페이지 그림(slides)을 쓰지 않았다. 글자만 줬기 때문일 수 있다.

## 2차 (프롬프트 수정 후)

프롬프트에 "숫자는 아라비아 숫자 그대로", "예시 계산은 직접 다시 세고 강의와 다르면 짚기"를 넣고 다시 돌렸다.

| | Sonnet 5.5 v2 | Terra v2 |
|---|---|---|
| 형식 검사 | 첫 시도 통과 | 첫 시도 통과 |
| 비용 | $0.150 (출력 1.3만 토큰) | $0.022 |
| 길이 | 문장 25, 실제 음성 144.5초 | 문장 23, 약 89초(추정) |
| 사실 | 맞음. "자료의 표에는 10단계지만 세어 보면 9단계" | 맞음. "직접 세면 10단계가 아닌 9단계" |
| 숫자 표기 | 숫자 | 숫자로 고쳐짐 |
| 화면 | 개인전 흐름도 + 배열 + 코드, 비교하는 칸 매번 강조 | 텍스트 + 배열 + 코드, 강조 꼼꼼해짐. 비유 그림 없음 |

- 11/11 샘플은 Sonnet v2를 쓴다([samples/clip-01/](../../samples/clip-01/README.md)). 부품을 더 다양하게 써서 FE 확인에 좋다.
- Terra는 1/7 가격에 거의 같은 품질이다. docs/06 절약 방법 2(설계도는 중간 등급)와 맞는다. 더 많은 클립으로 비교해 Q-AI-07에서 정한다.
- 실제 음성은 글자 수 x 0.15초 추정보다 길었다(약 0.19초/글자). 클립 길이 기준이 필요하다.
