# BUG-FE-02 · 개발 서버 포트 변경으로 PDF 업로드 연결 실패

> 상태: 원인 확인 · 담당: FE(기록·개발 서버), BE(CORS 설정 검토) · 최종 수정: 2026-11-14 · FE/Codex

- 발생: 2026-11-14 약 05:59 KST 조사. 사용자가 PDF 업로드 후 ‘업로드 확인 오류 / PDF 준비 상태를 확인해 주세요 / 서버에 연결하지 못했어요’를 보고했다. 사용자 브라우저의 실제 주소는 직접 확인하지 않았다.
- 분류: 개발 환경의 포트·CORS 불일치. 백엔드 중단이나 PDF 처리 로직의 결함으로 확정하지 않는다.
- [to:FE,BE] 확인 근거: Vite가 5173·5174·5175에서 동시에 실행 중이었다. 5173과 5175는 Codex frontend worktree, 5174는 Claude worktree였다. 백엔드 8000의 `/health`는 `status: ok`, `aiMode: sample`로 정상 응답했다.
- `Origin: http://localhost:5173` 요청에는 `Access-Control-Allow-Origin`이 있었지만, 5174 요청에는 없었다. BE 기본 허용값은 localhost/127.0.0.1의 5173뿐이다. 5175는 같은 기본 허용 목록에 없지만 별도 응답 검사는 하지 않았다.
- 재현 조건: 5173을 이미 사용 중인 상태에서 `npm run dev`를 추가 실행해 다른 포트로 열고, 기본 CORS 설정의 BE에 업로드 준비 요청을 보낸다. 브라우저가 허용되지 않은 Origin의 응답을 차단하면 FE는 일반 연결 실패로 표시한다.
- 임시 해결 안내: 기존 Codex 서버인 `http://localhost:5173`으로 접속. 추가 실행 대신 기존 개발 서버를 재사용한다. 안내 후 사용자 재시도 성공 여부는 미확인이다. 다른 담당자의 서버는 중단하지 않았다.
- 개선 검토(미확정·미구현): [to:FE] Vite `strictPort`로 조용한 포트 변경 방지. [to:BE] 병렬 개발에 필요한 명시적 Origin 목록을 `FRONTEND_ORIGINS`로 설정할지 협의(전체 허용 제안 아님). 일반 fetch 오류만으로 FE가 서버 중단과 CORS를 정확히 구별할 수 없으므로 오류 안내에는 주소·포트 확인 방법을 포함하는 방향을 검토한다.
- 이번 작업은 기록만 수행. 서버 설정·API·앱 코드 변경과 유료 호출 없음.
