# P-FE-10 · Ponytail 개인 환경 시험 사용 제안

> 상태: 의견 수집중 · 제안: FE/Codex · 2026-11-13 · 의견 마감: 다음 협업 논의 시

## 무엇을 정하려는가
[to:AI,BE] 불필요한 코드 생성과 토큰 사용을 줄이기 위해 각자 AI 개발 도구에서 **Ponytail을 선택적으로 시험 사용**하면 어떨까요? 팀 공통 필수 도구로 바로 지정하자는 제안은 아닙니다.

## 추천 방식
- 개인 환경에 설치하고 기본 `full` 모드로 작은 작업부터 시험합니다. 기존 코드·라이브러리 재사용, 필요한 부분만 수정, 불필요한 추상화·의존성·문서 생성을 줄이는 지침입니다.
- 기존 팀 지침과 역할 경계·제안/결정 절차를 우선합니다. 오류 처리·보안·접근성·필요한 테스트를 생략하는 용도로 쓰지 않습니다.
- 플러그인 파일과 개인 설정은 팀 저장소에 넣지 않습니다. FE의 개인 AGENTS.md 추가 지침도 커밋·main 병합에서 제외합니다. 공통 AGENTS.md 변경은 이번 제안 범위가 아닙니다.
- 설치와 Hook 신뢰 승인은 각 담당자가 직접 검토합니다. 다른 사람의 개인 설정·보안 권한은 바꾸지 않습니다. Codex와 Claude Code 설치 경로가 다르므로 각자 공식 설치 문서를 확인합니다.

## FE 시험 결과와 한계
FE 개인 Codex에 5.3.3을 설치했고 등록 활성화와 기본값 full을 확인했습니다. 사용자는 Hook 허용을 보고했습니다. FE 리팩토링에서 도달 불가 시제품 코드와 미사용 파일을 제거하고 모드 정의를 통합했으며 빌드·테스트 13개가 통과했습니다. **토큰·시간·비용 절감량은 실측하지 않았고 이 결과가 Ponytail만의 효과라고 단정하지 않습니다.** 실제 브라우저 확인도 별도입니다.

## 선택지와 평가
A. 원하는 담당자만 시험 후 유지 여부 결정(추천). B. 현재 도구·지침만 유지. 작은 실제 작업에서 변경 범위, 수정 소요, 회귀 오류, 확인 가능한 토큰/비용을 비교해 도움이 되는지 판단합니다. 새 자동 측정 시스템은 만들지 않습니다.
