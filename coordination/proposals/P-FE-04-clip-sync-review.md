# P-FE-04: A 클립 음성·자막·동작 싱크 공동 점검

> 상태: 의견 수집중 · 제안: FE/Codex · 2026-11-10 · 의견 마감: 11/11 피드백 시연 전

## 무엇을 정하려는가
A 클립의 원본 재생 약 54초(공유 녹화본 약 1분 6초)부터 싱크가 어긋난다는 제보를 AI·BE·FE가 함께 재현하고, 근거에 따라 수정 담당과 방식을 정한다. 현재 원인은 미확정이며 담당 잘못이나 계약 변경을 단정하지 않는다.

## 왜 지금 필요한가
- [녹화 자료](../reviews/fe/2026-11-10/README.md)와 Q-FE-04를 통해 A/B 피드백을 받는 중이며, 사용자가 위 구간의 싱크 문제를 전달했다. 지연 방향·크기·누적 여부는 아직 측정하지 않았다. 녹화 시각과 원본 시각의 차이를 일정한 12초 오프셋으로 가정하지 않는다(정지·탐색·녹화 시작 시점 확인 필요).
- 현재 samples/clip-01/result.json의 s4 lineIndex=2는 **52.2~56.75초**, “2단계, 6 대 2예요. 또 B의 2가 이겨요.”다. 이 문장에 setValue(g_c의 1번 칸에 2), unhighlight(g_ab의 1,1), move(p_j를 1,2), highlight(g_ab의 1,2)가 묶여 있다.
- [확정 시간 규칙](../../docs/04-video-blueprint.md#시간-규칙)은 문장 시작에 동작을 순서대로 실행한다. 현재 FE는 audio.currentTime으로 재계산하며 setValue·강조는 즉시, move는 최대 0.4초 이동을 표시한다. 따라서 비교를 설명하는 중 이미 결과·다음 포인터를 보여 주는 **의미상 시점 차이**가 생길 가능성이 있다. 이는 코드·설계도 대조에서 확인한 후보이고, 실제 녹화/음성을 대조해 원인을 확정한 결과는 아니다.
- 자동 상태 복원 검사는 시간표를 따른다는 근거다. 실제 발화와 시간표가 일치하는지, 브라우저가 지연 없이 표시하는지는 별도 확인한다.

## 공동 점검과 역할별 요청

| 역할 | 확인·공유할 내용 |
|---|---|
| FE | 원본 45·54·65·90초 전후에서 실제 audio.currentTime, caption(sceneId/lineIndex), 배열 값·강조·포인터를 대조. 처음부터 연속 재생과 같은 시점 직접 탐색을 비교해 렌더링 지연·상태 복원 문제인지 확인. 녹화 시각과 원본 시간을 따로 기록 |
| AI | 실제 A MP3에서 해당 문장의 발화 시작/끝과 captions 52.2~56.75초 비교. 음성 합치기의 문장/장면 쉼·길이 누적 확인. s4의 비교 설명과 결과 반영·다음 포인터 이동을 같은 문장에 묶은 것이 적절한지 검토 |
| BE | GET /clips/clip-01의 resultId·blueprint·captions와 /assets/clip-01-audio가 동일 A 결과 버전인지 확인. 원본 JSON/MP3와 제공 파일의 일치·캐시/교체 혼합 가능성 확인. 기존 Range 제공은 참고하되 싱크 정상의 증거로 대신하지 않음 |

기존 저장 결과만으로 조사한다. 유료 재생성·새 API·다른 역할 소유 파일 수정은 이번 제안의 실행 요청에 포함하지 않는다. 결과 버전은 클립 공개 ID와 구분해 기록한다.

## 선택지
### A. 원인 분리 후 담당 영역에서 수정
- 음성↔자막, 자막↔도형, 원본↔서버 응답, 브라우저↔녹화를 나누어 확인한다.
- 장점: 잘못된 전역 보정과 다른 구간 회귀를 피한다.
- 단점: 역할별 짧은 재현 결과가 먼저 필요하다.

### B. 문장을 비교/결과 단계로 나누기(의미상 동작 시점이 원인일 때)
- AI가 기존 계약 안에서 문장과 동작의 연결을 재구성한다. FE는 문장 시작 실행 규칙을 유지한다.
- 장점: 문장별 시간 계약으로도 설명과 화면 단계를 맞출 수 있다.
- 단점: 설계도·captions·음성을 같은 새 결과 묶음으로 맞춰야 한다. 재생성 비용·범위는 별도 확인한다.

### C. 문장 안의 세부 동작 시각 도입(기존 계약으로 해결이 어려울 때)
- 장점: 문장 도중 비교/결과/포인터 이동을 구분할 수 있다.
- 단점: 계약·검사기·생성기·FE 모두 영향을 받는다. 팀장 결정 전 새 필드나 임의 지연을 적용하지 않는다.

## 제안자의 추천과 이유
A부터 진행한다. 의미상 동작 배치가 원인이면 B를 우선 검토한다. 실제 시간표·FE·제공 파일 오류가 확인되면 해당 담당이 고친다. 원인 확인 없이 전체 자막/도형에 일괄 지연을 더하거나 C를 먼저 구현하지 않는다.

## 확인 기준과 기록 형식
- 기록: `작성자 / 확인한 resultId·커밋 / 원본 시간·녹화 시간 / 실제 발화 / 표시 자막 / 배열·포인터 / 기대 상태 / 원인 근거·수정 의견`.
- 제보 구간뿐 아니라 이전·이후 구간에서 고정 차이/누적 차이/특정 동작 차이를 구분한다.
- 수정 후 A 전체 재생·정지·탐색·반복과 B·parts-test 회귀를 확인한다. 새 버전이면 음성·captions·설계도를 함께 교체한다.
- 통과 허용 오차와 기대 동작 시점은 관찰 후 팀이 합의한다. 현재 수치 기준이나 해결 완료를 임의 확정하지 않는다.
