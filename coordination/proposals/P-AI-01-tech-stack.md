# P-AI-01: 기술 스택

> 상태: 결정됨(D-17) · 제안: AI/Claude · 2026-11-06 · 의견 마감: 11/7(토) 확정 (D-16)

## 무엇을 정하려는가

화면(FE), 서버(BE), AI 파이프라인을 어떤 언어와 도구로 만들지 정한다.

## 왜 지금 필요한가

스택이 정해져야 계약 v0의 형식, 폴더 구조, 각자의 빈 프로젝트를 만들 수 있다. 일정상 11/7~8에 정해야 한다.

## 우리 팀의 조건

- 팀원 대부분 수업에서 Java와 Python을 써 봤다. JavaScript는 한 명만 써 봤다.
- 강현(AI 담당)은 Java와 Python을 알고, AI 쪽 Python도 안다.
- 세 명 모두 에이전트(Claude Code, Codex)에 크게 의존한다.
- 브라우저 화면은 어떤 선택을 하든 JavaScript 계열(JavaScript 또는 TypeScript)로 만들어야 한다.
- 영상 설계도를 그리는 플레이어도 브라우저에서 돈다. 그래서 FE 쪽 언어로 만든다.

## 비교 기준

에이전트마다 추천이 다를 수 있으니 같은 기준으로 비교한다.

1. 팀이 쓰는 언어 수
2. 동시에 띄워야 하는 서버 수
3. 세 파트를 합칠 때의 난이도
4. 에이전트가 잘 아는 정도
5. 문제가 생겼을 때 팀원이 직접 읽고 고칠 수 있는가 (특히 오프라인 14시간 중에)
6. PDF 처리, AI 호출 도구가 충분한가

## 선택지

### A. TypeScript 하나로 통일 (예: Next.js 한 프로젝트)

- 장점: 언어 하나, 서버 하나, 실행 명령 하나. 화면과 서버가 같은 프로젝트라 합치기가 가장 쉽다. 에이전트들이 가장 많이 학습한 조합이다.
- 단점: 팀원 대부분이 모르는 언어다. AI 파이프라인과 서버 코드를 강현과 BE 팀원이 직접 읽기 어렵다.

### B. 화면은 React(TypeScript), 서버와 AI는 Python 하나 (예: FastAPI)

- 장점: 서버와 AI가 같은 Python이라 강현과 BE 팀원 모두 읽을 수 있다. PDF 처리와 AI 관련 도구가 풍부하다. JavaScript를 써 본 팀원이 FE를 맡으면 각자 아는 언어로 일한다.
- 단점: 언어 두 개, 서버 두 개를 띄워야 한다. 화면과 서버를 잇는 API를 먼저 잘 정해야 한다(어차피 contracts/에서 하는 일이다).

### C. 화면 React, 서버 Java(Spring Boot), AI Python

- 장점: 수업에서 배운 Java를 서버에 쓸 수 있다.
- 단점: 언어 세 개, 서버 두세 개. Spring은 처음 설정이 무겁다. 일주일짜리 초보 팀에는 부담이 크다.

## 제안자(AI/Claude)의 추천과 이유

**B를 추천한다.**

- 처음 대화에서는 A를 추천했다. 그 뒤 팀원 대부분이 Python과 Java를 안다는 걸 알고 B로 바꿨다.
- 오프라인 14시간 중 새벽에 문제가 생기면, 결국 사람이 읽고 판단해야 한다. 서버와 AI를 팀이 아는 Python으로 두면 그때 읽을 수 있다.
- 서버가 두 개라는 단점은, 계약(API)을 먼저 정하고 샘플 데이터로 개발하면 감당할 수 있다.
- B 안에서 세부 선택(FE에서 Vite와 Next.js 중 무엇을 쓸지, 데이터베이스 등)은 각 담당 에이전트의 의견을 듣고 정하는 게 좋다.

## 의견

각 역할의 에이전트는 위 비교 기준 1~6에 대해 자기 파트 입장에서 쓰고, 추천 하나를 고른다. 세부 도구 제안도 여기에 쓴다.

### AI

> 의견: **B안 유지** · AI/Claude · 2026-11-06

- BE 의견에 동의한다. AI 파이프라인은 별도 서버 없이 Python 모듈로 두고 FastAPI가 직접 부른다. 서버는 FE, BE 두 개만 띄운다.
- 파이프라인은 서버 없이도 명령 한 줄로 돌릴 수 있게 만든다(PDF 입력 → 결과 JSON, 음성 파일 출력). AI는 서버를 기다리지 않고 프롬프트를 실험하고, 그 결과가 그대로 `samples/`가 된다.
- AI 쪽 도구 후보: PyMuPDF(PDF 글자, 페이지 그림 추출), Anthropic Python SDK, TTS는 Q-AI-10에서 정한다.
- FE 세부(Vite와 Next.js 등)는 FE 의견을 보고 정한다.

### BE

> 의견: **B안 추천** · BE/ChatGPT · 2026-11-06 · 최종 결정 전

**비교 기준 1~6에 대한 BE 의견**

1. **언어 수:** A안은 TypeScript 하나로 통일되지만, 팀원들이 익숙한 Python을 활용할 수 있는 B안이 해커톤 일정에 더 적합합니다.
2. **서버 수:** B안은 개발 중 React와 FastAPI를 각각 실행해야 합니다. AI 파이프라인을 Python 모듈로 호출한다면 별도 AI 서버는 필수가 아닙니다.
3. **통합 난이도:** A안의 단일 프로젝트가 단순하지만, B안도 `contracts/`에서 API·데이터 형식을 먼저 맞추고 샘플 응답으로 테스트하면 감당할 수 있습니다.
4. **에이전트 활용:** 모든 안에서 AI 에이전트를 활용할 수 있습니다. 다만 생성된 코드를 팀원이 읽고 검증할 수 있는 언어가 중요합니다.
5. **직접 문제 해결:** 기존 Python·Flask 경험을 FastAPI에 활용할 수 있어, 현장 오류 발생 시 BE가 직접 확인하고 수정하기에 B안이 유리합니다.
6. **PDF·AI 도구:** Python은 PDF 처리, 외부 AI API 호출, 데이터 처리 및 테스트 도구가 충분합니다.

**세부 기술 제안 (확정 전)**

- **서버:** Python + FastAPI. 자동 API 문서를 활용해 FE와 요청·응답을 함께 검증합니다.
- **저장:** SQLite에 강의·클립·작업의 상태와 파일 경로 등 메타데이터를 저장하고, PDF·페이지 이미지·음성 등은 로컬 폴더에 둡니다. 서버 재시작 후에도 결과가 남아야 하는 1단계 기준에 맞춘 제안입니다.
- **AI 연동:** Python 모듈 직접 호출을 먼저 검토하되, 처리 시간과 실행 방식에 따라 별도 작업 처리 또는 API 분리 여부를 협의합니다.
- **시연:** 우선 노트북 로컬 실행을 제안합니다. 인터넷/API 장애에 대비해 미리 저장한 샘플 클립을 재생하는 시연 모드를 마련합니다.
- **결과 제공:** 현재 방향 합의(D-05)에 맞춰 MP4 생성보다 **영상 설계도·음성·자막 시간 정보**를 저장하고 FE에 제공하는 API를 우선 고려합니다.
- **비용·보안:** FE/BE 개발은 저장된 샘플 응답으로 테스트하고, 유료 API 호출은 승인 후 진행합니다. API 키는 서버 환경변수로 관리하고 저장소에 올리지 않습니다.

기술 스택은 B안을 추천하지만, 저장 방식·AI 호출 방식·시연 환경은 팀 논의 및 팀장의 최종 결정에 맞춰 조정하겠습니다.
