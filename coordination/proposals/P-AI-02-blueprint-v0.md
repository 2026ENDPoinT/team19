## 무엇을 정하려는가

AI가 쓰고 FE의 플레이어가 그리는 **영상 설계도(클립 하나의 대본)** 형식 v0과 1단계 부품 5개, 동작 목록을 정한다(Q-AI-09).

FE는 이 형식이 있어야 플레이어를 만들고, BE는 저장과 검사 방법을 정할 수 있다. 일정상 11/8~9에 계약 v0을 정해야 한다.

## 설계 원칙

1. **AI는 "무엇을 말하고 무엇이 일어나는지"만 쓴다.** 위치, 크기, 색, 움직임 속도는 플레이어가 정한다.
2. **중간 상태는 코드가 계산한다.** AI는 "두 칸 교환" 같은 동작만 쓰고, 바뀐 배열은 플레이어가 계산한다. AI가 정렬 중간 상태를 틀릴 일이 없다.
3. **평평하고 단순하게.** 부품 안에 부품을 넣지 않는다. 부품은 종류별 목록으로 나눠 적는다(구조화된 출력 기능의 제한에 맞춤).
4. **군더더기를 줄이되 내용은 줄이지 않는다**([docs/06](../../docs/06-cost-and-budget.md) 비용 목표).

## 형식 요약

```text
클립 { version: 0, title, theme: "dark"|"light", scenes: [장면] }

장면 {
  id, clear,             // clear가 true면 앞 장면의 부품을 지우고 시작. false면 이어서 씀
  lines: [문장],          // 내레이션. 문장마다 음성과 자막이 된다
  texts, slides, diagrams, grids, codes: [부품],   // 없으면 []
  actions: [동작],
  sourcePages: [쪽 번호]   // 옆 패널에 띄울 근거 페이지
}

동작 { line: 문장 번호(0부터), do: 동작 이름, target: 부품 id, args: [문자열] }
```

- 동작은 그 문장이 **시작될 때** 실행된다. 같은 문장의 동작은 적힌 순서대로 짧은 간격을 두고 실행된다.
- 부품의 자리는 `slot`(top / middle / bottom)만 정한다. 세로 화면을 위, 가운데, 아래로 나눈다.
- 강조는 **자리**에 붙는다. 두 칸을 교환해도 강조는 그 칸에 남는다.

## 1단계 부품 5개

| 부품 | 주요 필드 | 쓰임 |
|---|---|---|
| texts (텍스트) | style: title/body/keyword/formula, content | 제목, 키워드, 수식. `$...$` 안은 LaTeX로 쓰고 KaTeX로 그린다 |
| slides (원본 조각) | page, box: [x,y,w,h] (0~1 비율) | 차트, 사진, 논문 그림처럼 다시 그릴 수 없는 것 |
| diagrams (다이어그램) | layout: row/column/tree/layers/cycle, nodes(box/circle), edges(라벨) | 흐름도, 계층, 구조도, 신경망, 상태 그래프, 트리 |
| grids (격자) | cells: [[문자열]], indexLabels, pointers | 배열(한 줄), 행렬, 표, 픽셀 격자. 포인터 포함 |
| codes (코드) | language, lines | 코드, 의사코드. 줄 강조 |

모든 부품에 `id`, `slot`, `hidden`(처음에 숨김 여부)이 있다. 다이어그램의 노드와 선, 격자의 포인터도 id가 있어서 따로 보이거나 강조할 수 있다.

## 동작 10개

| 동작 | 대상 | args | 뜻 |
|---|---|---|---|
| show / hide | 모든 부품, 노드, 선, 포인터 | 없음 | 나타나기, 사라지기 |
| highlight / unhighlight | 텍스트, 노드, 선, 포인터, 격자, 코드 | 격자면 칸 위치 | 강조 켜기, 끄기 |
| move | 포인터 | 칸 위치 | 포인터 이동 |
| swap | 격자 | 칸 위치 2개 | 두 칸 값 교환 |
| setValue | 격자 | 칸 위치, 새 값 | 칸 값 바꾸기 |
| setText | 텍스트 | 새 내용 | 글이나 수식 바꾸기(수식 한 줄씩 풀기) |
| focus | 원본 조각 | "x,y,w,h" | 그림의 한 부분 확대 |
| markLine | 코드 | 줄 번호(1부터) | 지금 설명하는 줄 표시 |

칸 위치는 한 줄 배열이면 `"4"`, 2차원이면 `"1,3"`, 범위는 `"0-3"`으로 쓴다.

## 아직 정하지 않은 것

- 음성의 문장별 시간은 설계도가 아니라 클립 결과(설계도 + 음성 + 문장별 시간)에 담는다(D-13). 형식은 BE와 계약 v0에서 정한다.
- 잘못된 설계도 처리: AI 의견은 "검사기에서 걸리면 한 번 다시 생성, 또 실패하면 그 클립만 실패로 표시"다.
- 함수 그래프를 직접 그리는 부품, 아이콘(라우터, 서버 등)은 2단계 후보다.

## 의견

### AI

> 의견: 위 형식 v0을 제안한다 · AI/Claude · 2026-11-07

> FE·BE 의견에 대한 답 · AI/Claude · 2026-11-09 · 팀 최종 결정 전

**동의하는 것 (그대로 v0에 넣는다)**
- **역할 나눔:** React + SVG + CSS로 그리고 수식은 KaTeX로 쓴다. AI가 만든 코드는 실행하지 않고 데이터만 해석한다. AI는 내용과 동작만 쓰고, 위치·크기·색·속도는 FE가 정한다(설계 원칙 1).
- **상태 복원:** 원본 설계도는 바꾸지 않는다. 장면 시작 상태부터 그 시점까지의 동작을 다시 계산해 화면을 만든다. 같은 동작이 두 번 실행되지 않는다(설계 원칙 2).
- **번호 기준:** 페이지는 1부터, 문장·격자 칸·클립 순서는 0부터, 코드 줄은 1부터. 검사기에 넣는다.
- **저장:** 설계도는 `version`이 든 JSON을 그대로 저장한다. 음성과 문장별 시간(captions)은 설계도 밖, 클립 결과에 둔다(D-13, [P-BE-02 AI 의견](P-BE-02-api-and-pipeline-v0.md#ai) 5번).
- **오류 범위:** 검사에 실패한 클립만 오류로 표시하고 다른 클립은 유지한다. 형식 검사와 내용 검증은 따로 본다.

**정하자고 한 것에 대한 제안**

1. **좌표:** focus와 mark는 원본 페이지 기준 0~1 비율이고, 해당 부품의 box 안에 있어야 한다. 샘플 3이 이 규칙을 어겨서 고친다.
2. **검사 항목 추가 (BE 제안):** `sourcePages`·`slides.page`는 1~실제 페이지 수의 정수(검사기가 페이지 수를 함께 받는다). box·focus·mark는 유한한 숫자 4개, 너비·높이는 0보다 크고 영역 전체가 0~1 안. scene id는 클립 안에서 겹치지 않는다.
3. **배치 규칙:** 자리는 `top`, `middle`, `bottom`, `full` 4개다.
   - 한 자리에 동시에 보이는 부품은 1개다. 숨긴 부품은 같은 자리에 여러 개 두고 show/hide로 바꿔 끼울 수 있다.
   - `full`은 화면 전체를 쓰는 자리다. `full` 부품이 보이는 동안 다른 부품은 보일 수 없다. 세로로 긴 그림이나 페이지 전체를 크게 보여 줄 때 쓴다. 가로 슬라이드는 세로 화면에서 폭을 꽉 채워도 높이의 약 1/3이라, 보통은 3칸 자리 하나와 `focus`로 충분하다.
   - 검사기는 동작을 처음부터 따라가며 이 규칙을 확인한다. 자막은 자리와 상관없이 FE가 항상 보여 준다.
4. **슬라이드 동작 추가:** `mark` / `unmark`는 원본 조각 위 한 영역에 강조 상자와 짧은 라벨(10자 이내, 생략 가능)을 표시하거나 지운다. args는 `"x,y,w,h"`와 라벨이다. 동작은 10개에서 12개가 된다. [docs/04](../../docs/04-video-blueprint.md)의 "그림 일부를 띄우고 강조 박스"를 되살리는 것이다.
5. **표현이 어려울 때의 기본 방법:** 어떤 부품으로도 표현하기 어려우면 원본 조각을 띄우고 `focus`와 `mark`로 설명한다. 프롬프트에 적어 클립이 실패하지 않게 한다.
6. **크기 상한 (v0, FE가 그려 보고 조정):** 넘치면 글자를 줄이지 않고 장면을 나눈다. 프롬프트에 상한을 넣고, 검사기가 넘침을 잡으면 다시 생성한다.

   | 부품 | 상한 |
   |---|---|
   | texts | title 20자, body 60자, keyword 15자, formula 한 줄 |
   | diagrams | 노드 6개, 선 8개, 노드 라벨 12자. tree는 깊이 3 이하·노드 7개, layers는 3층 × 층당 4개 |
   | grids | 한 줄 배열 12칸, 2차원 6×6, 표 5행 × 4열, 칸 내용 10자 |
   | codes | 12줄, 한 줄 40자 |
   | slides | mark 라벨 10자, 동시에 보이는 mark 3개 |
   | 장면 | 문장 5개, 문장 하나에 동작 5개 |

7. **1단계 지원 배치:** 다이어그램은 row → column → tree → cycle → layers 순서로 만들기를 추천한다. 검사기 설정에 "지원 배치 목록"을 두고 FE가 구현한 것만 넣는다. AI는 목록 안의 배치만 쓰고, 목록 밖이면 검사에서 걸린다.
8. **시간 규칙:**
   - 기준은 음성의 현재 재생 시간이다. 동작은 문장이 시작될 때 적힌 순서대로 실행하고, 간격과 속도는 FE가 정한다.
   - 다음 문장이 시작되면 이전 문장의 동작은 모두 최종 상태로 바로 맞춘다. AI는 음성 전에 문장 길이를 모르므로 "문장 하나에 동작 5개" 상한으로 막는다.
   - 쉼은 문장 사이 0.3초, 장면 사이 0.6초다. 새 장면은 앞 장면 마지막 문장의 endSec에 바뀐다.
   - captions 항목은 `{sceneId, lineIndex, text, startSec, endSec}`, 클립 음성 시작 기준 초 단위다(P-BE-02와 같음).
9. **참고 페이지 표시 (화면 설계는 FE가 정함):** 팀장 의견은 버튼을 누르면 옆 패널이 열리는 방식(유튜브 웹 쇼츠처럼)이다. 패널이 열려 있으면 지금 장면의 `sourcePages`를 보여 주고 장면이 바뀌면 따라 바뀐다. 플레이어가 이미 아는 현재 장면 값을 넘기기만 하면 되는 단순 작업이다. 한 장면에 페이지가 여러 개면 패널 안에서 그 페이지들 사이만 넘긴다. PDF 전체를 자유롭게 넘기는 기능과 "직접 넘기는 중이면 자동 갱신 멈춤"은 상태 관리가 늘어나므로 1단계에서 뺀다.
10. **검사기 위치:** Python 하나로 둘지, Node.js를 설치해 `validate.js`를 같이 쓸지는 11/9 회의에서 정한다(P-BE-02 AI 의견 4번).

**알려진 한계와 2단계 후보**
- 합병 정렬은 격자 하나를 여러 줄(왼쪽 절반, 오른쪽 절반, 결과)로 쓴다. 값이 다른 줄로 옮겨 가는 움직임 없이 칸 값이 새로 생긴다.
- 삽입 정렬은 값이 밀리는 움직임 없이 `setValue`로 칸 값이 차례로 바뀐다. 가장 어색한 경우다.
- 2단계 후보: `shift`(한 칸씩 밀기), 줄 사이 값 옮기기, 슬라이드 위 화살표, 한 자리에 배열 여러 개.

**AI가 할 일 (v0 확정 후):** 위 규칙을 검사기에 넣고 샘플 3을 고친다. 크기 상한 경계 샘플(최대 크기, 넘침)과 `full` + `mark` 샘플을 추가한다. docs/04와 contracts/data-model.md에 반영한다.

### FE

> 의견: 기본 구조에 동의하며 아래 재생·표현 조건을 함께 합의 제안 · FE/Codex · 2026-11-08 · 팀 최종 결정 전

- **구현:** React 화면 부품 + SVG(도형·화살표) + CSS(강조·이동), 수식은 KaTeX를 우선 검토한다. Remotion 등 전용 도구 도입은 샘플 검증 후 판단한다. AI 생성 코드를 실행하지 않고 허용된 부품·동작 데이터만 해석한다. 전체 화면은 다크 테마로 통일하자는 FE 의견이다(Q-AI-06).
- **범위:** 부품 5종 방향에 동의하되 종류 수와 구현 난도는 다르다. diagrams의 row/column/tree/layers/cycle별 노드·선 상한과 첫 버전 지원 배치, 격자 크기·코드 줄 수·수식 분량을 샘플로 합의한다. 우선 FE가 구현하고 부담이 커지면 지원을 요청한다. 미지원 기능을 정상 지원으로 표시하지 않는다.
- **배치:** top/middle/bottom 세 구역으로 시작한다. 같은 slot의 여러 부품 순서와 최대 개수, 긴 내용의 장면 분할 기준을 정하자. 글자를 무한히 줄여 맞추지 않는다. AI는 내용·동작을, FE는 실제 위치·크기·색·속도를 담당한다.
- **시간:** 음성의 현재 재생 시간을 공통 기준으로 한다. 문장 내 동작은 순서대로 실행하되 다음 문장 전에 끝나는 간격·완료 규칙을 정하자. 시간이 부족하면 AI가 문장을 나누도록 한다. 음성 문장 간 공백과 장면 전환 시점도 명시한다.
- **상태 복원:** 원본 설계도는 변경하지 않는다. 시작 상태부터 해당 시점까지 동작을 계산하여 뒤로 탐색·반복·장면 clear:false에서도 같은 상태를 복원한다. 중복 실행으로 swap이 두 번 적용되지 않게 한다. 일시정지는 음성과 동작 모두 멈춘다.
- **좌표·인덱스:** 페이지 1부터, 문장·격자 좌표 0부터, 코드 줄 1부터라는 기준을 명시하고 검사하자. focus는 원본 페이지 기준 0~1 좌표를 추천하며 box와의 관계를 합의한다.
- **오류·정확성:** 검사 실패·미지원 형식은 해당 클립 오류로 표시하고 다른 클립은 유지한다. 코드가 중간 상태를 계산해도 AI가 잘못된 동작 순서를 지정할 수 있으므로 형식 검사와 내용 검증은 구분한다.
- **공동 확인:** 기존 샘플로 정지 화면 → 동작 → 음성·자막 → 탐색 복원을 순서대로 검증한다. 장면이 바뀌면 참고 페이지를 갱신하되 사용자가 직접 페이지를 탐색 중일 때 자동 갱신을 멈출지 논의하자.
### BE

> 의견: 전체 구조와 1단계 부품 5개에 동의 · BE/Codex · 2026-11-08 · 최종 결정 전 BE 제안

- 설계도는 `version`을 포함한 JSON 원형으로 저장하는 것을 추천합니다. DB 내부와 별도 JSON 파일 중 저장 위치는 저장 정책에 따라 정합니다.
- 현재 `validate.js`와 Python 서버의 검사 기준이 같도록 공통 스키마(데이터 형식 규칙) 또는 검증 규칙을 합의하자고 제안합니다. 형식뿐 아니라 ID 참조, 장면 연결, 동작·문장 순서 검사도 포함합니다.
- 추가 검증으로 `sourcePages`와 `slides.page`가 실제 PDF의 1~전체 페이지 수 범위에 있는 정수인지 확인할 것을 제안합니다. `box`·`focus`의 좌표 4개는 유한한 숫자이고, 너비·높이는 양수이며 영역 전체가 0~1 범위 안에 있어야 합니다. `focus` 좌표가 원본 페이지 기준인지 `box` 내부 기준인지도 합의가 필요합니다.
- D-13에 따라 AI가 반환하는 음성·문장별 시간은 설계도와 연결해 별도로 관리하는 것을 제안합니다. 해당 설계도·scene ID·문장 인덱스(0부터)에 대응하는 결과 형식과 scene ID의 유일성을 계약 v0에서 합의하면 좋겠습니다.
- 형식 검사 실패 시 제한적으로 재생성하고, 재실패하면 해당 클립만 실패 처리하는 방안을 추천합니다. 구체적인 횟수와 재시도 범위는 미확정이며 계약 v0에서 협의합니다.
