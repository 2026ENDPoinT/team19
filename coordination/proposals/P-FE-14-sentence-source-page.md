# P-FE-14 · 설명 문장별 원본 페이지 연결

> 상태: 논의중 · 담당: FE · 최종 수정: 2026-11-14 · FE/Codex

[to:AI,BE] 사용자 요청: AI가 영상 설명을 만들 때 각 문장의 대표 근거 PDF 페이지도 함께 전달하고, FE는 재생 중인 문장에 맞춰 원본 한 장을 전환한다. 장면 전체의 `sourcePages`만으로는 이 연결을 알 수 없다. [Q-FE-14](../questions.md#q-fe-14--toaibe--열림) 후속 요청이다.

## 최소 전달안 (미확정)
- AI 설계도 단계에서 장면의 `lines`와 같은 길이·순서로 문장별 대표 페이지를 지정한다. 예: `lineSourcePages: [3, 3, 4]`. 여러 쪽을 종합한 문장은 가장 직접적인 근거 쪽 하나를 고른다. 근거를 특정할 수 없는 도입·전환 문장은 `null`로 명시하고 추측하지 않는다.
- 지정한 페이지는 해당 장면의 `sourcePages`와 실제 PDF 페이지 범위 안에 있어야 한다. AI 검사기가 길이·타입·페이지 범위를 검사한다.
- AI 음성 생성은 이 연결을 유지하고, BE 결과 응답에서 FE가 `sceneId + lineIndex`로 읽을 수 있도록 전달한다. 기존 captions가 이미 이 두 값을 제공하므로 별도의 시각 추정은 필요하지 않다. 필드 이름·정확한 위치는 AI·BE 검토 후 팀장이 확정한다.
- FE는 현재 captions의 문장에 연결된 페이지 한 장을 표시한다. 정지·탐색·반복도 재생 시각으로 다시 계산한다. 문장 사이 공백은 직전 명시 페이지를 유지하고, 장면 진입·데이터 없음·`null` 처리 정책은 확정 시 함께 정한다. 근거를 알 수 없는 페이지를 ‘설명 중’이라고 표시하지 않는다.
- 기존 샘플에는 새 정보가 없을 수 있으므로 기존 대표 원본 표시를 유지한다. 자동 재생성·유료 호출은 하지 않는다.

## 역할별 요청
- **AI:** 생성 프롬프트·검사기에서 문장별 대표 페이지를 함께 만들 수 있는지 검토하고 기존 구조에 더 작은 변경안이 있으면 제안해 주세요.
- **BE:** 장면/문장 연결 정보가 저장·결과 응답에서 누락되지 않는지 검토해 주세요. 별도 API가 필요한지는 먼저 협의합니다.
- **FE:** 계약 확정과 연결 정보가 있는 샘플 수령 후 재생 문장 기준 원본 전환을 구현합니다. 새 필드를 임의로 계약에 추가하지 않습니다.
