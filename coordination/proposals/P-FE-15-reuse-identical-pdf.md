# P-FE-15 · 같은 PDF의 기존 강의 재사용

> 상태: 논의중 · 담당: FE(제안), BE(구현 검토) · 최종 수정: 2026-11-14 · FE/Codex

[to:BE,AI] 사용자 요청: 내 강의함에 이미 있는 PDF를 다시 올리면 새 강의를 추가하지 말고 기존 강의를 열어 주세요. 기존 중복 항목도 한 항목으로 볼 수 있어야 합니다. 파일명만으로 합치지 않습니다.

## 제안 동작
- 같은 ownerId 안에서 PDF 바이트의 SHA-256으로 동일 파일을 판별합니다. 이름이 달라도 내용이 같으면 재사용하고, 이름이 같아도 내용이 다르면 별개입니다. 내용이 같은 다른 PDF 편집본까지 의미적으로 합치는 기능은 범위 밖입니다.
- 기존 강의가 ready이면 기존 lectureId와 preparationJobId를 돌려주고 추출·해설을 새로 실행하지 않습니다. pending/running이면 진행 중인 같은 작업을 반환합니다. 동시에 같은 파일을 올려도 새 작업이 둘 생기지 않도록 원자적으로 처리합니다.
- failed 자료는 성공한 자료처럼 재사용하거나 자동 재시도하지 않습니다. 실패 원인을 알리고 별도 재시도 정책을 협의합니다. 추출 버전이 바뀌어 재처리가 필요한 경우도 중복 재사용과 구분합니다.
- ownerId가 없거나 다른 사용자의 자료면 교차 재사용하지 않습니다. 샘플/실제 모드의 저장소가 섞인 경우도 잘못 재사용하지 않도록 실행 모드·자료 호환성을 확인합니다.
- 이미 저장된 중복은 원본 PDF 해시와 소유자를 확인해 목록에서 대표 강의 한 건으로 묶는 방안을 검토합니다. 기존 ID·클립·링크는 보존합니다. 이 요청은 기존 DB 행·PDF·클립을 삭제하거나 강제 병합하는 승인이 아닙니다. 대표 선택 시 준비 상태와 기존 완성 클립을 함께 고려해 주세요.

## 기존 FE 연결
현재 `uploadPdf`는 lectureId/jobId를 받아 `watchPreparation`에서 같은 작업과 강의를 읽습니다. BE가 기존 두 ID를 그대로 반환하면 재사용 경로도 사용할 수 있습니다. 새 API는 우선 요구하지 않습니다. 선택적 `reused` 표시나 ready 응답 변경이 필요하면 FE와 먼저 맞춰 주세요. 기존 모드 outline은 조회로 재사용하고, 없는 학습 모드는 사용자 모드 선택 흐름에 따라 생성합니다.

## 확인 요청
- **BE:** 해시 저장·기존 자료 확인 방식, 동시 업로드 중복 방지, 같은 소유자 범위, failed 처리와 기존 중복 목록 표시안을 검토해 주세요. 파일명·크기만 비교하는 FE 임시 병합은 하지 않습니다.
- **AI:** 같은 PDF라도 수정된 추출·프롬프트 때문에 재처리가 필요한 경우 기존 결과 재사용과 구분하는 의견을 주세요. 이번 요청만으로 유료 재생성은 하지 않습니다.
- **FE:** 계약 확정 후 재사용 응답이 현재 준비·모드 선택·강의함에 정상 연결되는지 검증하고 필요한 안내를 추가합니다. 아직 중복 방지 기능이 구현됐다고 표시하지 않습니다.

## 완료 기준
같은 사용자·같은 PDF의 반복/동시 업로드가 한 강의·한 준비 작업으로 연결되고, 다른 내용·다른 사용자 자료는 합쳐지지 않습니다. 기존 중복 항목도 대표 한 건으로 표시하되 기존 저장 결과는 보존합니다.
