# P-FE-06: 긴 단계 설명의 세로 배치 지원 앞당기기

> 상태: 의견 수집중 · 제안: FE/Codex · 2026-11-10 · 의견 마감: 다음 샘플 배치 수정 전

## 무엇을 정하려는가
D-34에서 11/11 이후로 둔 column 지원을 앞당겨, 가로로 길어지는 단계 설명을 세로로 보여 주자고 제안한다. 사용자는 지침의 현재 범위와 차이를 설명받은 뒤 제안서 작성·FE 구현에 동의했다. 정식 범위 변경은 팀장이 기록한다.

## 왜 지금 필요한가
A의 ‘팀 간 개인전’ 단계(맨 앞끼리 비교 → 승자 저장 → 다음 선수 등판)가 가로 3개 상자로 표시돼 글자가 작아진다는 피드백이다. 세로 영상에서는 넓은 상자를 위→아래로 연결하는 편이 읽기 쉽다. 배열·트리는 구조와 방향에 의미가 있어 별도로 유지한다.

## 선택지
### A. 기존 row를 FE에서 자동으로 세로로 바꾸기
현재 결과에도 바로 적용되지만 row의 가로 의미를 바꾸고, AI가 의도한 배치를 알기 어렵다.
### B. 기존 column 값을 FE에서 지원하고 AI가 선택하기
형식 v0에 이미 있는 값이므로 새 필드는 필요 없다. 검사기 지원 목록과 생성 규칙·샘플 반영은 AI 담당과 합의해야 한다. B안을 추천한다.

## 제안자의 추천과 이유
B안. 3개 이상 단계 설명이나 예상 가로 폭이 좁은 영상에 맞지 않는 흐름도에는 column을 우선 검토하고, AI가 의미와 가독성에 따라 결정한다. 기존 row를 FE가 임의로 재해석하지 않는다.

## 영향받는 문서와 파트
- [to:AI] 승인 후 pipeline/validate.py의 SUPPORTED_LAYOUTS에 column을 추가하고 관련 검사를 갱신해 주세요. 긴 단계 설명에 column을 고르는 프롬프트 규칙과 해당 A/B 설계도의 배치 수정도 검토해 주세요. 단순 배치 변경이면 유료 재생성을 자동 실행하지 말고 필요한 범위를 판단해 주세요. samples는 FE가 직접 수정하지 않습니다.
- [to:BE] 새 API는 요구하지 않습니다. 공식 AI 검사기가 column을 허용한 뒤 기존 결과 제공 경로로 처리 가능한지 확인 부탁드립니다. 승인 전 검사기를 우회하지 않습니다.
- FE: frontend에 column 렌더링·상자/연결선·이름 표시와 1/3/6개 노드 범위 검사를 추가했다. 기존 row/tree와 샘플 원본은 유지한다. FE 기능 코드는 미커밋이며 main 병합 전 사용자 확인한다.
- [to:AI] 팀장 승인 시 decisions.md·plan-first-clip.md 등 지원 범위를 갱신해 주세요. 현재 이 제안으로 D-34나 공식 지원 목록을 바꾸지 않습니다.

## 확인 기준
노드 순서대로 위→아래 배치, 아래 방향 연결선, 강조·숨김·탐색 복원 유지. 노드와 라벨이 잘리지 않고 전체가 영상 영역에 맞아야 한다. 최종 실제 샘플 재생 확인은 별도로 필요하다.
