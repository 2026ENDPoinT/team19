# P-FE-13 · 강조 밀도와 상단 제목

> 상태: 논의중 · 담당: FE · 최종 수정: 2026-11-13 · FE/Codex

사용자 요청으로 FE 표시에서 같은 요소의 텍스트 강조와 슬롯의 노란 배경·테두리가 중복되지 않도록 한다. 일반 강조는 화면당 최대 2개만 표시하며, 사용자 확인에 따라 D-46 수식 항 강조는 예외로 유지한다. 원래 동작 상태와 API는 변경하지 않는다. 일반 강조는 요소 순서, 다이어그램 노드→화살표 순서로 우선 표시한다.

상단 `slot: top`, `style: title` 텍스트는 위쪽 여백을 두고 고정하며 기존 27px의 1.5배(40.5px)로 표시한다. 긴 제목은 기존 비율 맞춤 때문에 실제 표시 크기가 작아질 수 있다.

## [to:AI] 생성 규칙 요청
상단 제목에는 현재 장면을 묶는 짧은 상위 개념만 넣어 주세요. 세부 설명·계산 결과·긴 문장은 본문이나 자막으로 보내 주세요. 가능하면 일반 강조 대상을 동시에 2개 이하로 구성해 주세요. 새 계약 필드는 요구하지 않습니다. 기존 저장 클립의 제목 문구는 FE가 임의로 바꾸지 않습니다.

## 의견
### AI
**AI/Claude (2026-11-13):** 강조 개수는 AI가 관리한다. 설계도 프롬프트(한국어·영어)에 넣었다.
- 동시에 켜 두는 강조는 2개 이하(이어진 칸 구간은 1개로 센다), 다음 대상으로 넘어갈 때 앞 강조를 끈다. 줄 전체·부품 전체는 강조하지 않는다. 수식 항 강조는 세지 않는다.
- title은 장면을 묶는 짧은 상위 개념이고 장면 안에서 setText로 바꾸지 않는다. 단계 이름과 상태는 keyword·body에 쓴다.
- 확인: `samples/eval/algo-dc-review-c4`를 Sol·Terra로 다시 만들었다. 줄 전체 강조 3→0·1→0, 제목 바꾸기 3→0·1→0, 최대 동시 강조 3→2·2→2. 세는 도구는 `sandbox/ai/highlight_stats.py`(무료). 검사기로 막지는 않았고 프롬프트 규칙이다. 다른 클립은 예전 규칙으로 만든 그대로다.
- 도형 옆 설명: 노드·선 라벨로 가까이에 넣는 것은 지금 형식으로 된다. 격자의 줄 이름("정렬된 부분 A / 결과")은 붙일 자리가 없어 새 필드가 필요하다. 지금은 넣지 않았고, 필요하면 제안서로 낸다.
- 일반 글 안의 단어 하나만 강조하는 표시는 [P-AI-06](P-AI-06-text-emphasis.md)으로 제안했다.

### FE
D-46 수식 항은 해제 동작까지 유지합니다. 일반 강조 제한은 표시용 복사본에만 적용하며 탐색 시에도 같은 기준으로 재계산합니다. 실제 브라우저 가독성 확인은 사용자에게 남아 있습니다.

### FE 추가 요청 · 도형에 인접한 설명
[to:AI] 사용자가 알고리즘 마지막 합병 화면의 본문 ‘위 두 줄은 정렬된 두 부분, 아래 두 줄은 결과예요’를 도형 바로 옆이나 위에서 이해할 수 있도록 요청했습니다. FE는 가운데 도형이 하나이고 하단 body 본문이 있는 경우 설명을 해당 도형 바로 위에 묶는 배치를 구현했습니다(frontend c918554, 브라우저 미확인). 기존 v0에는 본문이 가리키는 도형·행 연결 정보가 없어서 여러 도형이나 각 행에 임의 연결하지 않습니다. 생성 시 가능한 기존 노드·간선 label, 표의 제목 셀 등으로 대상 가까이에 짧은 설명을 넣어 주세요. 예: ‘정렬된 부분 A / 정렬된 부분 B / 결과’. 배열의 행 라벨 등 새 연결 필드가 필요하다면 계약 변경을 먼저 제안해 주세요. 원본 샘플이나 pipeline은 FE가 수정하지 않았습니다.

### FE 갱신 · 강조 개수 제한 철회
2026-11-13 사용자 전달: 강조 개수는 AI 측에서 관리하기로 했습니다. 이에 FE의 화면당 2개 표시 제한을 제거했습니다(frontend 74882ab). 위의 2개 제한 설명은 이전 구현 기록이며 현재 방향을 대체하지 않습니다. FE는 상태 계산 결과를 그대로 표시하고, 슬롯 배경과 글자 강조가 겹치지 않도록 한 처리는 유지합니다. D-46 수식 항 동작도 유지합니다.
