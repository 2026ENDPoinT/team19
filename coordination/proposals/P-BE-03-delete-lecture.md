# P-BE-03: 내 강의함 PDF 영구 삭제 (`DELETE /lectures/{id}`)

> 상태: 의견 수집중 · 제안: BE/Claude · 2026-11-14 · 사용자와 FE 담당자가 직접 B안(영구 삭제)으로 합의했고 FE가 공식 요청 [Q-FE-20](../questions.md)을 올렸다. 팀장 결정 전이다. BE 구현은 기능 브랜치 `feature/be-delete-lecture`에서 끝냈고 **main 병합 전**이다.

[to:FE] 사용자가 내 강의함에 올린 PDF를 더 보관하고 싶지 않을 때 본인이 지울 수 있게 합니다. 목록에서 숨기는 기능이 아니라 **원본 PDF와 연결된 강의 데이터·생성 결과·저장 파일을 실제로 삭제**합니다.

## 합의된 요구사항 (출처)
**FE 담당자와 사용자가 직접 B안(실제 PDF·클립·데이터 영구 삭제)에 합의했다.** FE는 이후 공식 요청 Q-FE-20을 올렸다(선택 버튼 → 강의 체크 → 제거 버튼, 여러 개는 FE가 하나씩 `DELETE`). 같은 PDF의 강의 전체 삭제 정책은 BE 구현안이며 **팀장의 확정 결정은 아니다.**

## API (BE 구현 완료, 미병합)
`DELETE /lectures/{lectureId}` · 요청 헤더 `X-Owner-Id`(삭제에서는 **필수**)

| 결과 | 의미 |
|---|---|
| `204` 본문 없음 | 삭제 성공 |
| `404 LECTURE_NOT_FOUND` | 없는 강의, **또는 요청한 소유자의 강의가 아님**(다른 사람의 강의가 있는지 알려 주지 않는다). 소유자 없는 옛 강의도 404 |
| `422 INVALID_REQUEST` | 헤더 없음·형식 오류 |
| `409 LECTURE_BUSY` | 이 자료의 작업이 **실행 중**이라 지금은 삭제 불가. 아무것도 지우지 않는다. 끝난 뒤 다시 시도 |
| `503 STORAGE_UNAVAILABLE` | 파일이 사용 중이라 옮기지 못했거나 저장소(SQLite) 오류. 롤백·복구되어 아무것도 삭제되지 않았고 다시 시도 가능 |
| `500 STORAGE_CLEANUP_PENDING` | 목록에서는 이미 삭제됐지만 파일 정리가 끝나지 않음. 서버를 다시 켜면 자동으로 정리한다. FE는 목록을 새로 조회하면 된다 |

CORS `allow_methods`에 `DELETE`를 추가했다. `GET`·`HEAD`·`POST`는 그대로다.

## FE 호출 방식과의 일치 (Q-FE-20)
- FE 제안(`DELETE /lectures/{id}` + `X-Owner-Id`, 성공 `204`, 다른 주인·없음 `404`, 여러 개는 하나씩)과 **그대로 일치**한다. 새 선택·체크 UI에 BE가 더 필요한 것은 없다.
- 선택한 항목마다 한 번씩 순차 호출하면 되고 항목 사이는 독립이다. 한 항목이 실패해도 나머지 호출에 영향이 없다.
- **일괄 삭제의 주의:** 같은 PDF의 강의는 한 번에 함께 삭제된다. 목록에는 대표 한 건만 보이므로 그 대표 id만 보내면 된다. 같은 묶음의 다른 id가 선택에 섞여 먼저 삭제됐다면 그 호출은 `404`이며, **FE는 404를 "이미 없음(삭제된 것으로 취급)"으로 처리**하는 것을 권한다.

### 응답별 FE 처리 (각 항목의 DELETE마다)
| HTTP · `error.code` | 뜻 | FE 처리 제안 |
|---|---|---|
| `204` | 삭제됨 | 성공으로 표시 |
| `404 LECTURE_NOT_FOUND` | 없음, 이미 삭제됨, 다른 소유자 | 이미 없음으로 보고 성공 취급 |
| `409 LECTURE_BUSY` | 이 자료의 작업이 실행 중 | 이 항목은 건너뛰고 "만드는 중이라 끝난 뒤 삭제할 수 있어요" 안내. 선택 유지 |
| `422 INVALID_REQUEST` | `X-Owner-Id` 누락·형식 오류 | FE 버그. 재시도 안 함 |
| `503 STORAGE_UNAVAILABLE` | 파일 사용 중 또는 저장소 오류. **아무것도 삭제되지 않음** | 잠시 뒤 다시 시도 안내(`retryable: true`) |
| `500 STORAGE_CLEANUP_PENDING` | **목록에서는 이미 삭제됨**, 파일 정리만 남음(서버 재시작 때 자동 정리) | 삭제된 것으로 취급하고 목록 새로 조회 |
오류 본문은 `{"error": {"code", "message", "retryable"}}`이다. 모든 호출이 끝나면 목록을 한 번 새로 조회한다.

## 삭제 범위
- **같은 소유자가 올린 같은 PDF(SHA-256)의 강의 기록 전체**를 한 번에 삭제한다. 내 강의함은 같은 PDF를 한 항목으로 묶어 보여 주므로, 대표 하나만 지우면 옛 중복이 다시 나타나기 때문이다. 해시가 없는 옛 강의는 저장된 `original.pdf`를 읽기만 해 비교한다. 파일명은 보지 않는다. 다른 PDF·**다른 소유자의 같은 PDF**·소유자 없는 옛 강의는 지우지 않는다. 다른 AI 모드(sample/real)에서 만든 같은 PDF도 목록에서 묶여 있으면 함께 지운다.
- **DB:** `lectures`, `pages`, `outlines`, `clips`, `jobs`(준비·분할·클립과 재시도 이력), `job_usage`, `assets`. 외래 키 순서(자식 먼저)로 지운다.
- **파일:** `ROOT/lectures/{id}/`(원본 PDF·페이지 이미지)와 `ROOT/clips/{clipId}/`(음성·미리보기 MP4·재시도 결과). ROOT 안의 실제 폴더만 대상이며(심볼릭 링크·id 형식 불일치는 제외) DB에서 읽은 경로를 그대로 믿지 않는다. 공용 개발 샘플(`stored_sample`)은 DB와 무관해 영향이 없다.
- 삭제한 ID(강의·Outline·클립·Job·자산 주소)는 이후 조회·재시도가 404이고, 같은 PDF를 다시 올리면 **새 강의·새 Job**이 만들어진다(기존 ID 재사용 없음).

## 실행 중·대기 중 Job
- 한 SQLite 쓰기 트랜잭션(`BEGIN IMMEDIATE`) 안에서 확인하고 지운다. **`running`이 하나라도 있으면 409**이며 이미 시작된 유료 호출을 끊으려 하지 않는다.
- `pending`은 같은 트랜잭션에서 Job 행과 함께 지운다. 이미 실행기 대기열에 있던 작업은 Job이 사라져 실행되지 않는다(실행 시작이 `pending→running` 한 번의 원자적 갱신이라 삭제와 동시에 시작할 수 없다). 삭제 도중 새 작업·재시도는 트랜잭션이 끝날 때까지 기다리다 강의가 없어 404가 된다. 스레드 경쟁 테스트로 "반쯤 지워진 강의"가 없음을 확인했다.

## DB와 파일의 일관성
SQLite와 파일은 한 트랜잭션으로 묶을 수 없어 다음 순서를 쓴다: ① 지울 폴더를 `ROOT/.trash/<토큰>/`으로 이동(이름 바꾸기, 매니페스트 기록) ② DB 삭제를 커밋 ③ 휴지통 폴더 삭제.
- ①이 실패(파일 사용 중 등)하거나 ②가 실패하면 폴더를 원래 자리로 되돌리고 DB는 롤백한다 → 아무것도 삭제되지 않는다(503 또는 오류).
- ③이 실패하면 DB는 이미 삭제된 상태로 `500 STORAGE_CLEANUP_PENDING`을 알리고, 서버 시작 때 `.trash`를 정리한다. 시작 시 매니페스트의 강의가 DB에 **아직 있으면(커밋 전 중단) 폴더를 되돌리고**, 없으면 삭제를 끝낸다.

## 보안 한계 (반드시 유지)
`X-Owner-Id`는 인증이 아닌 **기기 식별자**다(D-50). 이 값을 아는 사람은 그 소유자의 강의를 **영구 삭제할 수 있다.** 강한 인증이 된다고 말하면 안 되며, 삭제의 취소·복구는 없다. 더 강한 보호(계정, 서명 URL)는 후순위 방향이다.

## FE에 요청 (FE 화면·버튼은 BE가 수정하지 않았다)
1. 삭제 버튼과 **영구 삭제 확인 창**(복구 불가, 같은 PDF의 모든 기록이 함께 삭제됨, 만든 영상 포함).
2. `DELETE /lectures/{id}`에 `X-Owner-Id`를 함께 보내고 `204`면 내 강의함 목록을 새로 조회.
3. `409 LECTURE_BUSY`는 "만드는 중이라 끝난 뒤 삭제할 수 있어요"로 안내, `500 STORAGE_CLEANUP_PENDING`은 목록을 새로 조회(이미 삭제됨).
4. 삭제 직후 보고 있던 강의·클립은 404가 되므로 화면에서 정리.
5. 실제 브라우저 검증은 아직 하지 않았다.

## 검증 (BE, 무과금)
임시 SQLite·임시 폴더·가짜 AI로 신규 테스트 24개(`backend/tests/test_delete_lecture.py`, 여러 강의 순차 삭제·응답별 코드 구분 포함). 최신 main 병합 후 전체 회귀 결과는 보고에 있다. 포함: 전 테이블·파일·후속 조회 404, 소유자 불일치·헤더 오류, 중복 전체 삭제와 다른 PDF·다른 소유자 보존, 재업로드 새 ID, 실행 중 409, 대기 중 Job과 동시 삭제, 파일 이동 오류·DB 오류 복구, 정리 실패와 재시작 복구, ROOT 밖 경로 보호, CORS.
